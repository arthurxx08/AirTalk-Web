# AirTalk Web v0.6

## 目的
iPhone 1台に接続したAirPods 1組を2人で片耳ずつ使用する構成を試す版です。

- 自分モード：iPhone内蔵マイクを取得し、Web Audio APIで左チャンネルへ出力
- 相手モード：AirPodsマイクを取得し、右チャンネルへ出力
- AirPods側のiOS設定は「マイク：常に右」に固定する想定
- 1つの入力を交互に使う半二重方式（同時通話ではありません）
- 左右チャンネル確認用の440Hzテスト音を搭載

## GitHub Pagesへの反映
ZIPを展開し、既存リポジトリのファイルを上書きしてください。`icons/`、`manifest.webmanifest`、`sw.js`も含めて配置します。GitHub Pages反映後、Safariでページを再読み込みしてください。PWAをホーム画面に追加済みの場合、古いキャッシュが残る場合はSafari側でページを再読み込みし、必要に応じてホーム画面のAirTalkを終了して開き直してください。

## 最初の操作
1. AirPodsを接続し、iOSのBluetooth設定でマイクを「常に右」にする。
2. AirTalkを開き「マイクを許可してデバイスを読み込む」を押す。
3. 自分側の欄にiPhone内蔵マイク、相手側の欄にAirPodsマイクを選ぶ。自動判定が違う場合は手動で選び直す。
4. 「左だけテスト」「右だけテスト」で左右出力を確認する。
5. 「自分が話す」「相手が話す」で入力を切り替える。

## 技術上の制約
- `enumerateDevices()` にiPhone内蔵マイクとAirPodsマイクが別々に表示される必要があります。
- 入力は `getUserMedia()` の `deviceId` 指定で切り替えます。Safari/iOSの実装や権限状態により、切替時に確認表示が出る場合があります。
- 出力は `StereoPannerNode` で左(-1)／右(+1)へ振り分けます。
- AirPodsのマイクを使うBluetooth HFP経路では、iOSが出力をモノラル化したり音質・ルートを変更する場合があります。その場合、左右分離ができないことがあります。
- WebアプリからAirPodsの「マイク：常に右」設定自体を変更するものではありません。
- 実機での動作確認は未実施です。左右チャンネルテストと入力切替をiPhone上で確認してください。


## v0.6での修正
- 入力切替時に旧マイクを先に停止していた処理を変更。
- 新しいマイク入力を取得・AudioContextへ接続してから旧入力を停止する「make-before-break」方式に変更。
- AudioContextと音声出力グラフを切替時に作り直さず維持。
- 切替失敗時は、取得済みの旧入力をできるだけ維持。
- 実機でのAirPodsルート維持は未確認。iOS Safari側が入力デバイス変更に伴って出力経路を変更する場合、Webアプリだけでは完全に固定できない可能性があります。
